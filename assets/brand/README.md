# Apple Health AI Bridge visual identity

This identity is a restrained public-release baseline for Apple Health AI Bridge: a local-first, read-only bridge that turns Apple Health history into useful context for AI tools.

It is intentionally developer-tool oriented rather than consumer wellness or clinical branding.

## Naming relationship

Apple Health AI Bridge is the open-source project behind Health Bridge for AI.

- Use **Apple Health AI Bridge** for the product, repository, website, CLI display headings, and public documentation.
- Use **Health Bridge for AI** only when identifying the existing App Store or TestFlight listing.
- Use **Health Bridge** only as the compact in-app label where space benefits from the shorter name.
- Keep `apple-health-ai-bridge`, `health-bridge`, and `health_bridge` unchanged as package, CLI/MCP, and Python identifiers.

These names describe one product system. Do not imply that the repository and App Store product are separate products, and do not imply Apple affiliation.

## Regenerating assets

The canonical assets are generated by `tools/generate_brand_assets.py`. Run the
full native export from the repository root:

```bash
uv run --with pillow --with playwright python tools/generate_brand_assets.py
```

The full export includes seven SVGs, eight brand PNGs, two source HTML files, and
the existing AppIcon catalog with 18 slots, 15 PNGs, and `Contents.json`. When
exporting site assets, `--site-root` also writes the header master SVG, favicon
SVG, 180px Apple touch icon, and matching social-card HTML and PNG.

If Playwright has no Chromium browser on a fresh machine, install one with
`uv run --with playwright python -m playwright install chromium` before
regenerating rasters. If Chromium is already installed outside Playwright's
current cache, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/absolute/path/to/chrome`.

## Asset direction

- **Logo:** the no-hex mark shared by the master and favicon. Keep its three paths
  and `translate(48 52) scale(1.3) translate(-48 -52)` transform; omit the
  hexagonal outline and facets. Use the same geometry at every size, with no
  separate two-stroke favicon.
- **Primary tile:** `#111827` charcoal blue.
- **Fallback dark tile:** `#080A0F` near black.
- **Mark colors:** retain the existing transparent light and dark mark roles and
  the near-black tile variant. Keep icon artwork free of gradients and canonical
  PNG exports opaque RGB.
- **Core line:** `Your Apple Health, connected to your AI.`

## Lockup and social cards

The lockup is a 1440×360 composition with a 176px tile, 88px horizontal
padding, and a 44px gap. Set the product name, `Apple Health AI Bridge`, on the
first line at 64px and weight 700. Set `Your Apple Health, connected to your AI.`
on the second line at 36px in `#475569`. Do not add a technical third line,
border, or rounded card. Use a white base with a mint `rgb(15, 159, 130)` wash
at 5% opacity in a 62%×140% ellipse fading to transparent at 78%, and a blue
`rgb(37, 99, 235)` wash at 3.5% opacity in a 60%×130% ellipse fading at 78%.
The HTML, PNG, and vector exports share this composition.

Social cards use native 1280×640 and 1200×630 canvases, 64px outer padding and
mark, a 28px product name, and an 80px headline with 1.04 line height. Use
`Your Apple Health, connected to your AI.` as the headline and
`Ask your AI about your sleep, workouts and activity.` as the 40px `#475569`
subtitle. Keep a 20px address and neutral hairline. Their `#fbfcfd` base uses a
mint wash at 9% opacity in a 70%×110% ellipse fading at 75%, and a blue wash at
6% opacity in a 65%×100% ellipse fading at 75%. Do not add grids, glow, fake
controls, colored edge bars, or gradient lettering.

## Copy guidance

Primary public copy:

- `Your Apple Health, connected to your AI.`
- `An open-source bridge that turns health history into useful AI context.`
- `Open-source · local-first · read-only by default`

Use implementation details as secondary proof, not hero copy. Avoid leading public visuals with `HealthKit`, `SQLite`, `MCP`, arrows, or cloud/no-cloud claims unless the surface is explicitly technical documentation.

## Small-size rules

- Keep the current mark as the single maintained mark family for now.
- Do **not** use `vector-effect: non-scaling-stroke` in the logo SVG; internal strokes must scale with the viewBox.
- Export favicon/app-icon rasters from the SVG source at the target size, not by CSS-scaling a screenshot.
- Re-check 16/24/32px output whenever mark geometry changes.

## Usage rules

Do:

- Use the charcoal tile for avatars, App Store icon, GitHub profile-style surfaces, and dark lockups.
- In the README, pair the existing 80px mark with a native text heading. Keep the
  heading as text rather than replacing it with lockup artwork.
- Use the lockup exports where a standalone branded composition is needed.
- Use the social-card PNG/HTML for GitHub social preview and announcement drafts.
- Keep screenshots synthetic or scrubbed; never show real health values or private receiver/setup material.

Do not:

- imply Apple affiliation;
- use the Apple logo, Apple Health app icon language, red heart mark, ECG line, medical cross, hospital motif, or clinical imagery;
- suggest diagnosis, emergency use, coaching decisions, recovery scoring, or medical interpretation;
- show real HealthKit values, receiver endpoints, pairing URLs, bearer tokens, token hashes, cursor values, local outbox contents, or screenshots with personal health values;
- make the implementation nouns the main visual message.

## QA requirements

Before publishing or committing visual changes:

1. Parse SVG/XML and asset catalog JSON.
2. Verify every AppIcon PNG listed in `Contents.json` exists at the expected pixel size.
3. Confirm iOS AppIcon PNGs are opaque RGB square images; iOS applies the mask.
4. Inspect the social card, lockup, 1024px app icon, and favicon sizes visually.
5. Confirm no logo SVG contains `vector-effect: non-scaling-stroke`.
6. Check that public preview images contain no real health data, tokens, endpoints, pairing material, or private screenshots.
